Isaac Sim 5.1.0 · RTX 50-series · checked September 2026

Isaac Sim crashes on open with a 595.xx driver

Isaac Sim 5.1.0 crashes at startup on RTX 50-series (Blackwell) cards running any 595.xx NVIDIA driver. The fix is to downgrade to Studio Driver 591.74. I hit this on September 2, 2026, on an RTX 5080 running driver 595.95, while setting up our robotics workstation.

01

Confirm it is this bug

The crash shows up in omni.kit.window.preferences or rtx.scenedb.plugin.dll. Those are symptoms. NVIDIA staff on the Isaac Sim developer forum put the real cause in the Vulkan rendering path on the 595.xx driver branch.

nvidia-smi

If the driver version starts with 595, this is your crash. Windows logs are in C:\Users\<user>\AppData\Local\ov\logs\Kit\.

02

Downgrade to Studio Driver 591.74

  1. Download Studio Driver 591.74 from NVIDIA's driver page.
  2. Run the installer, choose Custom (Advanced), and tick Perform a clean installation.
  3. Reboot.
  4. Clear C:\Users\<user>\AppData\Local\ov\cache before relaunching. Shader caches are driver-specific, and a stale one looks exactly like the bug coming back.
Studio, not Game ReadyNVIDIA staff have said Game Ready drivers are not validated for Omniverse applications. I treat the Studio branch as a requirement.
If 591.74 still crashesFall back to 580.88, NVIDIA's officially tested driver for Isaac Sim 5.1.0. It is old for Blackwell, so try 591.74 first.
03

Stop the driver from coming back

Turn off automatic driver updates in the NVIDIA App. On a managed machine, Windows Update will push 595.xx back down at the next patch cycle and break Isaac Sim again, so ask IT to hold the driver version.

What does not fix itClearing the shader cache on its own, forcing the D3D12 renderer in GUI mode, disabling the hotkeys extension, changing Isaac Lab versions, and rebuilding the conda environment. Others tried all of these before me.
If you cannot downgrade yetHeadless mode with the D3D12 renderer runs fine even on the broken driver. RL training is headless anyway, so the bug blocks looking at the simulation, not training in it.
Why I did not upgrade to Isaac Sim 6.0 insteadIsaac Sim 6.0 with Isaac Lab 3.0.0-beta2 runs on current drivers. But unitree_rl_lab, the training repo I use for our Go2, targets Isaac Lab 2.3.0 exactly. Putting it on a beta with a major version bump means debugging someone else's API migration. My decision: pin the driver, not the stack, and move to 6.0 when the training repo does.
